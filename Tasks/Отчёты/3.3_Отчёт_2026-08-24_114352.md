## Что было не так (факт по коду)

- Модалка «🗂 Сессии» (`server/static/dashboard.html`) не имела фильтра по статусу:
  бэкенд `GET /api/sessions?status=` уже умеет фильтровать (`app.py:1470-1472`),
  UI звал его без `status`.
- Не было массовых операций: cleanup-эндпоинт `POST /api/sessions/cleanup`
  (`app.py:1576-1601`) вообще не вызывался из панели (инцидент 2026-08-23:
  59 мёртвых сессий чистились вручную SQL-ом); массового kill stalled тоже не было.
- Заметка сессии обрезалась до 60 символов без опознавания префикса `handoff:`
  (кандидаты рестарта — механика 8.4/6.2), бейджа и сортировки вверх не было.
- Форма «➕ Новый агент» была жёстко спрятана `style="display:none"`
  (`dashboard.html`, `.agent-create`) — «➕»-кнопки для её вызова не существовало.

## Что сделано (пути файлов)

Файл: `D:\Projects\dev-pipeline\server\static\dashboard.html`

1. **Фильтр статуса**: `<select id="sessionsFilter">` (все статусы / stalled / failed /
   killed / done) над таблицей субагентов; `onchange` → `loadSessions()`, значение
   подставляется в `GET /api/sessions?project=…&status=…`; счётчик в шапке дополнен
   `(фильтр: …)`.
2. **«🧹 Очистить завершённые»** (`sessionsCleanup`): чекбокс
   `#cleanupKeepHandoff` («сохранить handoff», checked по умолчанию) →
   `POST /api/sessions/cleanup?project=…&keep_handoff=1|0`; `confirm()` с предупреждением;
   результат в тосте: «Удалено: N, handoff сохранено: M».
3. **«⛔ Kill stalled»** (`killAllStalled`): `confirm()` → выборка
   `/api/sessions?status=stalled` текущего проекта → последовательный `POST
   /api/sessions/{sid}/kill` по каждому; тост «Stalled убито: N, ошибок: M».
4. **Бейдж handoff**: в `renderSessionTable` заметки с префиксом `handoff:` получают
   бейдж «🤝» перед текстом и сортируются наверх (`.sort` по признаку `handoff:`).
5. **«➕ Новый агент»**: кнопка в шапке модалки показывает/скрывает `.agent-create`
   (`toggleAgentCreate`, `display:flex/none`); форма горизонтально разложена
   (`align-items:center;gap:8px`).
