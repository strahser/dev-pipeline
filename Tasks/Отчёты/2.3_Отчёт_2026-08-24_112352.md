# ОТЧЁТ: 2.3 — stage_approver в жизнь: конфиг, полный вход, тесты тега

Дата: 2026-08-24
Статус: done

## Что было не так
- `runner.stage_approver` не был задан ни в одном из 8 examples — механика 6.3
  (`runner.stage_approver=reviewer`) оставалась спящей (config.py:264 читает
  значение по умолчанию `owner`).
- Промпт ревьюера этапа (`REVIEWER_PROMPT`) передавал `{card}` только последней
  листовой карточки — ревьюер не видел отчёты/вердикты остальных карточек этапа.
- `_tag_stage_done` (:369) не имел ни одного теста; тег ставился ДО коммита плана
  (run():788-791), т.е. якорь `stage/N-done` указывал бы на родительский коммит
  без финального состояния (статус done); повторный вызов на существующем теге
  падал и возвращал "".

## Что сделано
1. **Конфиг** `examples\devpipeline\pipeline.yaml`: в секцию `runner` добавлен
   `stage_approver: reviewer` с комментарием о механике (карточка 2.3/6.3).
2. **Полный вход ревьюера** `agents\plan_runner.py`:
   - новый метод `_stage_review_files(card)` — формирует явный список файлов
     отчётов/вердиктов ВСЕХ листовых карточек этапа двойным glob
     `<этап>.*_Отчёт_*.md` и `<этап>.*_Вердикт_*.md`;
   - `REVIEWER_PROMPT`: строка «Отчёты/вердикты карточек этапа: …{card}_*.md»
     заменена на «Отчёты/вердикты ВСЕХ листовых карточек этапа (явный список
     файлов):» с плейсхолдером `{stage_files}`;
   - `_request_stage_review` передаёт `.replace("{stage_files}", self._stage_review_files(card))`.
3. **Тегирование** `agents\plan_runner.py`:
   - `_tag_stage_done` стал идемпотентным: сначала `git tag -l name` — если тег
     уже есть, возвращает имя, не падая; иначе ставит и возвращает имя.
   - Порядок в `run()`: теперь `set_card_status(done) → _git_commit(плана) →
     _tag_stage_done`, чтобы якорь включал финальное состояние (комментарий в коде).
4. **dry-run**: выводит строку `[dry-run] approver этапа: <значение>`.
5. **Тесты** `tests\test_plan_runner.py` (класс `StageTagAndInputTest`):
   - `test_tag_stage_done_creates_and_is_idempotent` — тег создаётся; повторный
     вызов безопасен и возвращает имя;
   - `test_tag_after_plan_commit_anchors_final_state` — тег указывает на HEAD
     после коммита плана, финальное состояние (done) в коммите;
   - `test_stage_review_files_lists_all_leaf_cards` — список содержит отчёты и
     вердикты всех листовых карточек этапа, чужие файлы не попадают;
   - `test_reviewer_prompt_contains_full_stage_file_list` — промпт ревьюера
     содержит явный список файлов всех листовых карточек этапа;
   - `test_dry_run_shows_approver` — dry-run выводит строку про approver=reviewer.
