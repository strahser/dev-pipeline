# ОТЧЁТ: 1.3 — continues в agent_create: handoff-цикл `up` замкнут

Дата: 2026-08-24, карточка 1.3 плана 2026-08-24_dev-pipeline-crew-manager-ui.
Статус: **done**.

## Что было не так (факт по коду)

1. `supervise_once` кладёт в инструкцию рестарта флаг `continues: True`
   (pipeline\crew.py:197), а `agent_create` (POST /api/agents,
   server\app.py:1387) — НЕТ: сессии, поднятые
   `python -m pipeline.cli up` и кнопкой «▶ Поднять проект», шли без флага.
2. Воркер пишет заметку «handoff:<путь>» только при этом флаге
   (agents\session_worker.py:269–271: `note = HANDOFF_MARK+path if
   instr.get("continues") and handoff_path`), а done без марки супервизор
   пропускает (pipeline\crew.py plan_restarts:
   `if status == "done" and not note.startswith(HANDOFF_MARK): continue`).
   Итог: handoff-цепочка для основного пути (`up`) была разомкнута на первом
   звене — критерий приёмки 6.2.3 не выполнялся.

## Что сделано

1. **server\app.py (agent_create)** — в инструкцию ролевой сессии добавлен
   `"continues": True` (с комментарием на карточку 1.3). Теперь и рестарты
   супервизора, и свежие сессии `up`/«▶ Поднять проект» несут одинаковый
   контракт: воркер при rc=0 + отчёт + handoff помечает сессию
   `handoff:<путь>`, и `plan_restarts` планирует продолжение.
2. **tests\test_server.py (AgentSpawnTest)** — новый тест
   `test_instruction_has_continues_flag`: POST /api/agents для ролей
   executor/controller возвращает сессию с `instruction.continues is True`
   (критерий приёмки №1).
3. **tests\test_crew.py** — новый класс `UpHandoffLoopTest`
   (интеграционный, с worker-заглушкой; критерий приёмки №2):
   - `test_up_session_done_with_handoff_restarts` — ролевая сессия с
     instruction {prompt/skill/role/task, continues=True} завершается
     воркером как при реальном флаге — done + заметка `handoff:<путь>`;
     `supervise_once` планирует restart, преемник получает промпт
     «исходная инструкция + содержимое handoff» («РОЛЬ+СКИЛЛ+АВТОЗАДАНИЕ»
     и «ХВОСТ-ПОРЦИИ» в prompt новой сессии) и наследует `continues`.
   - `test_up_session_done_without_handoff_not_restarted` — контроль правила
     «супервизор перезапускает только сессии, которые сами попросили
     продолжения»: done БЕЗ марки handoff → 0 решений.

Код вне задания не менялся (session_worker.py и crew.py правок не требуют —
механика уже соответствовала контракту, отсутствовал только флаг).

## Открытые вопросы и ограничения

- Ролевая сессия БЕЗ ключа `report` в инструкции при rc=0 завершается веткой
  «отчёт не требуется» (session_worker.py:262–268) — заметка без маркера
  `handoff:`, и супервизор такую сессию по done НЕ продолжает. Это
  соответствует правилу crew.py «перезапускаем только тех, кто сам попросил
  продолжения»; критерий №2 карточки покрыт на сценарии done+handoff
  (ветка session_worker.py:269–274 при флаге continues). Если владельцу нужно,
  чтобы чисто завершившиеся ролевые агенты тоже зацикливались по handoff —
  отдельная карточка (меняет семантику «попросил продолжения»).
