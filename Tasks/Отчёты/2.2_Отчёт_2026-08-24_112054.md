# ОТЧЁТ: 2.2 — Изоляция stage-ревьюера во временном worktree

Дата: 2026-08-24
Статус: done

## Что было не так

`_request_stage_review` (agents/plan_runner.py) запускал ревьюера этапа на живом
корне проекта с полными правами — в промпт подставлялся `{root}` = `self.cfg.root`,
git-команды исполнялись на рабочем репозитории, а единственной защитой был текст
промпта. Ревьюер физически мог править код продукта. У независимой reviewer-фазы
(`_semantic_review`, карточка 4.2) уже был готовый паттерн изоляции:
`_worktree_add`/`_worktree_remove` (git worktree add на HEAD → чтение только в
временной копии → удаление после решения), но stage-ревью его не использовал.

## Что сделано

- `agents/plan_runner.py`
  - `REVIEWER_PROMPT` переписан: вместо `{root}` — `{wt_root}` (путь временного
    worktree), добавлено явное указание «Твоя рабочая копия — временный git
    worktree; Читай код ТОЛЬКО в ней; ничего не редактируй и не коммить»;
    git-команды (`git -C "{wt_root}" log/show`) переведены на worktree.
  - `_request_stage_review` теперь переиспользует worktree-хелперы:
    создаёт временный worktree через `_worktree_add`, запускает ревью-сессию с
    промптом на `{wt_root}`, и в `finally` всегда снимает worktree через
    `_worktree_remove`. Ревьюер физически изолирован от живого корня.
  - Мягкий режим: если `git worktree` не создан (нет git/коммитов) — событие
    `stage_review_unavailable`, печать предупреждения, этап ждёт владельца,
    карточка не блокируется (паритет с механизмом 4.2).
- `tests/test_plan_runner.py` (`CheckpointApproverTest`)
  - `setUp` инициализирует git-репозиторий (как в `SemanticReviewTest`), чтобы
    worktree реально создавался.
  - `test_reviewer_approves_stage` усилен: проверяет, что промпт ревью-сессии
    содержит «git worktree», «ТОЛЬКО в ней», НЕ ссылается на живой корень, и что
    временный worktree снят после решения.
  - Новый `test_git_worktree_refusal_is_soft_mode`: git-репозиторий без коммитов →
    `git worktree` отказывает → ревьюер не запускается, предупреждение, этап
    ждёт владельца (`_wait_decision`), карточка не блокируется, нет мусорных
    временных каталогов.

## Доказательства

правки вне его, worktree удаляется после решения:


assertNotIn живой корень / `_worktree_count()==1`).

доходит: `test_reviewer_approves_stage` — план закрыт, `approve` принят.

`test_git_worktree_refusal_is_soft_mode` — rc=0, ревьюер не запускался,
`_wait_decision` вызван, карточка done.
