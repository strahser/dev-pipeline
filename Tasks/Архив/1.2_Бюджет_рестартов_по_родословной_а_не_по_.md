# КАРТОЧКА 1.2 — Бюджет рестартов по родословной, а не по sid

## Цель
`restart_policy.max_restarts` ограничивает ЦЕПОЧКУ порций одной работы, а не отдельную запись в БД — супервизор физически не может штормить.

## Описание (факт по коду)
plan_restarts ведёт counters по sid (:99), а каждый рестарт создаёт новый
  sid со свежим счётчиком → лимит недостижим по цепочке поколений. Дополнительно failed
  перезапускается «всегда» (:97) — вместе с багом 1.1 это дало морг из десятков сессий.

## Входные данные
pipeline\crew.py (plan_restarts, supervise_once);
  agents\project_manager.py (manage_once — тот же counters); tests\test_crew.py.

## Задание

## Что проверяем

- **Критерии приёмки**:
