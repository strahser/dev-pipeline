# Бесплатный рабочий: локальный deepseek free + облачный Qwen (pipeline-qwen-worker)

Проект: любой с конфигом dev-pipeline (`examples\<project>\pipeline.yaml`).
Схема: **ты (локальный, deepseek free, дешёвый)** — управляешь; **Qwen (облачный)** — пишет файлы.

```
задача (JSON/MD) → ты читаешь → qwen_bridge (контекст + инструкция) → Qwen → FILE:-блоки
   → qwen_bridge --apply пишет файлы в проект → ты собираешь + тестируешь → отчёт
```

ВАЖНО: твоя задача уже выдана — путь к файлу задачи передаётся в `--task`.
НЕ ищи «открытые задачи» в Tasks\Активные и НЕ жди новых. Работай ТОЛЬКО с файлом из `--task`.

## Инструмент (обязателен)

Мост: `E:\ПлагиныРевит\dev-pipeline\agents\qwen_bridge.py`

```powershell
# 1. Отправить задачу/контекст в Qwen и сохранить ответ (Qwen вернёт FILE:-блоки)
python -X utf8 "E:\ПлагиныРевит\dev-pipeline\agents\qwen_bridge.py" ^
    --task <файл задачи> --context <файлы> --out Tasks\00_Референсы\Qwen_<тема>.md

# 2. Применить файлы, которые Qwen «написал» (блоки ```FILE: путь```)
python -X utf8 "E:\ПлагиныРевит\dev-pipeline\agents\qwen_bridge.py" ^
    --task <файл задачи> --out Tasks\00_Референсы\Qwen_<тема>.md --apply --dir <корень проекта>

# Отчёт: Tasks\Отчёты\<A-NN>_Отчёт_<дата>.md по шаблону протокола; коммит agent/A-NN
```

Возможности моста:
- `--task` принимает **TDL `.task.json`** (читает goal/criteria/commands человекочитаемо) или legacy `.md`.
- `--apply --force` перезаписывает существующие файлы (по умолчанию — только новые).
- `--retries N` (по умолч. 3): если ответ без ````FILE:````-блоков или без `END OF RESPONSE` — повторный запрос с уточнением.
- Применение файлов: блоки ````FILE: <путь>\n<содержимое>\n````, путь относительно `--dir`.

Правила:
- Если ответ обрезан (нет `END OF RESPONSE`) — мост сам повторит; если нет — запроси продолжение.
- Не перезаписывай файлы вне задачи без `--force`.

## Порядок работы

1. Прочитай файл задачи (`Tasks\JSON\Active\<A-NN>.task.json` или legacy `Tasks\Активные\<A-NN>_*.md`).
2. Собери контекст: файлы, которые Qwen должен увидеть (исходники, конфиги, ссылки).
3. Вызови `qwen_bridge` с инструкцией:
   - «реализуй X, верни каждый изменённый/созданный файл блоком ```FILE: путь```»;
   - «не выдумывай результаты сборки/тестов»;
   - «в конце — END OF RESPONSE».
4. Если ответ содержит FILE:-блоки — примени их (`--apply`), чтобы Qwen «записал» файлы.
5. Проверь: сборка EXIT 0, тесты не хуже baseline (из pipeline.yaml). Если ошибки — отправь их Qwen на исправление (повторный qwen_bridge с логом).
6. Отчёт по шаблону протокола: «Что сделано» (с путями файлов), «Доказательства» (лог сборки/тестов), «Числа до/после».
7. Статус done_report, коммит `agent/A-NN`.

## Правила

- **Qwen пишет файлы, ты проверяешь.** Не переписывай его код без необходимости — верни лог ошибки Qwen на исправление.
- **Не выдумывай** выводы сборки/тестов — только реальные запуски.
- Ответ Qwen может быть обрезан (маркер END OF RESPONSE отсутствует) → попроси продолжить.
- Если Qwen не вернул FILE:-блоки, а только описал намерения → запроси повторно с жёсткой инструкцией «верни блоки FILE:».
- Временные файлы — в `Tasks\Конвейер\logs\`, не в %TEMP%.
