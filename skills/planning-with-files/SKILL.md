# Planning with Files

Работай как Manus: используй persistent Markdown-файлы как «рабочую память на диске».

## Где какие файлы

| Место | Что кладётся |
|---|---|
| Каталог скилла (`D:\Projects\dev-pipeline\skills\planning-with-files\`) | шаблоны, справка |
| **Твой рабочий каталог** (корень задачи/проекта) | `task_plan.md`, `findings.md`, `progress.md` |

Файлы планирования живут рядом с кодом, а не в каталоге скилла.

## Быстрый старт

Перед ЛЮБОЙ сложной задачей (3+ шага, >5 tool calls):

1. Создай `task_plan.md` (фазы, прогресс, решения) — по шаблону
2. Создай `findings.md` (исследования, находки)
3. Создай `progress.md` (журнал сессии, результаты тестов)
4. Перечитывай план перед решениями
5. Обновляй после каждой фазы: `in_progress` → `complete`, ошибки, файлы

## Согласование с конвейером dev-pipeline (ВАЖНО)

- Конвейер уже ведёт источник истины: `Tasks\JSON\Active\A-NN.task.json` (статусы, даты, история) и `Tasks\Активные\A-NN_*.md` (постановка задачи).
- Файлы этого скилла — **рабочая память исполнителя внутри сессии**: план подзадач, находки, протокол ошибок. Они НЕ заменяют TDL-задачу и НЕ меняют её статус (статусы — только через tdl-* команды).
- Отчёт по задаче — по шаблону конвейера в `Tasks\Отчёты\A-NN_Отчёт_<дата>.md` (с доказательствами: EXIT 0, vstest N/M, grep).
- В конце сессии можно удалить `task_plan.md`/`findings.md`/`progress.md`, если их содержание перенесено в отчёт (антипаттерн: оставлять их в коммите как мусор — не коммить без нужды).

## Ядро паттерна

```
Context Window = RAM (нестабильная, ограниченная)
Файловая система = Диск (persistent, безлимитный)

→ Всё важное пишется на диск.
```

## Назначение файлов

| Файл | Назначение | Когда обновлять |
|---|---|---|
| `task_plan.md` | Фазы, прогресс, решения | После каждой фазы |
| `findings.md` | Исследования, открытия | После ЛЮБОЙ находки |
| `progress.md` | Журнал сессии, результаты тестов | В течение сессии |

## Критические правила

### 1. Сначала план
Никогда не начинай сложную задачу без `task_plan.md`.

### 2. Правило 2 действий
> «После каждых 2 операций просмотра/браузера/поиска НЕМЕДЛЕННО сохрани ключевые находки в файлы.»

Предотвращает потерю визуальной/мультимодальной информации.

### 3. Читай перед решением
Перед крупными решениями читай файл плана — цели в окне внимания.

### 4. Обновляй после действия
После завершения фазы: `in_progress` → `complete`; логируй ошибки; фиксируй созданные/изменённые файлы.

### 5. Логируй ВСЕ ошибки
```markdown
## Errors Encountered
| Error | Attempt | Resolution |
|-------|---------|------------|
| CS0246: тип не найден | 1 | Добавлен using/ссылка на проект |
| vstest: 43 упавших DI-тестов | 2 | known-issue окружения (домашний ПК) |
```

### 6. Не повторяй неудачи
```
if action_failed:
    next_action != same_action
```

## Протокол 3 попыток

```
ПОПЫТКА 1: Диагностика и фикс
  → Внимательно прочитай ошибку → найди корневую причину → точечный фикс

ПОПЫТКА 2: Альтернативный подход
  → Та же ошибка? Другой метод/инструмент/библиотека
  → НИКОГДА не повторяй точь-в-точь провалившееся действие

ПОПЫТКА 3: Пересмотр шире
  → Поставь под вопрос допущения → ищи решения → обнови план

ПОСЛЕ 3 ПРОВАЛОВ: эскалация пользователю/контролёру
  → Объясни, что пробовал → покажи конкретную ошибку → спроси совета
```

## Матрица «читать vs писать»

| Ситуация | Действие | Причина |
|---|---|---|
| Только что записал файл | НЕ читай | Контент ещё в контексте |
| Посмотрел изображение/PDF | Пиши findings СЕЙЧАС | Мультимодальное → текст, пока не потеряно |
| Браузер вернул данные | Пиши в файл | Скриншоты не сохраняются |
| Начало новой фазы | Читай план/findings | Переориентация |
| Произошла ошибка | Читай релевантный файл | Нужно текущее состояние для фикса |
| Возобновление после паузы | Читай все файлы планирования | Восстановить состояние |

## Тест «5 вопросов» при перезагрузке

| Вопрос | Источник ответа |
|---|---|
| Где я? | Текущая фаза в task_plan.md |
| Куда я иду? | Оставшиеся фазы |
| Какая цель? | Постановка цели в плане |
| Что я узнал? | findings.md |
| Что я сделал? | progress.md |

## Когда использовать

**Использовать:**
- Многошаговые задачи (3+ шага)
- Исследовательские задачи
- Построение/создание проектов
- Задачи с множеством tool calls
- Всё, что требует организации

**Пропустить:**
- Простые вопросы
- Правки одного файла
- Быстрые справки
